# Проверка и подготовка к сдаче

## Фактически выполнено в среде подготовки

1. TS/TSX исходники синтаксически обработаны предустановленным Babel (preset-typescript и syntax-jsx). Это НЕ замена TypeScript type checking и НЕ React production build.
2. Тесты преобразованы в JS Babel с CommonJS и запущены Node.js test runner.
3. Пройдено 31 из 31 теста. Лог находится в tests/TEST-RESULTS.txt.
4. npm install --offline не смог завершиться, поскольку в кэше нет @types/react и других зависимостей проекта. Сетевые запросы не выполнялись. Vite build, tsc, npm test через tsx и визуальный браузерный прогон здесь не выполнялись.

## Что покрывают тесты

- Корректность размеров, bpp, DPI для 6 форматов.
- PNG RGBA, 1-bit grayscale, отсутствие физического разрешения, pHYs после IDAT.
- JPEG grayscale, progressive, DQT, пересчёт JFIF px/cm, Exif/JFIF conflict с приоритетом Exif.
- TIFF LZW, BigTIFF, настоящий big-endian TIFF, некорректное смещение IFD.
- Отказ для неизвестных и обрезанных данных; определение формата без расширения.
- Малый объём чтения JPEG при большом Blob.
- Очередь Engine: каждое задание ровно один раз, ограничение workers, пустой список, отмена, ошибка worker.
- Относительные пути и отказ для >100 000 файлов.

Изображения в tests/fixtures созданы для проекта средствами Pillow/tifffile. Все базовые картинки 37×23; mono.png — 17×11. В PCX генератор записал 100×100 DPI, тест сверяет именно поле заголовка. Это не архив преподавателя и не исчерпывающее покрытие вариантов форматов.

## Перед сдачей — обязательный ручной прогон

1. Установить зависимости: npm install.
2. Выполнить npm test, npm run build. Исправить любые выявленные ошибки окружения/версий.
3. Запустить npm run dev или production preview, выбрать tests/fixtures и сравнить таблицу с тестами.
4. Проверить папку с вложенными каталогами, одинаковыми именами в разных подпапках, кириллицей и пробелами.
5. Проверить поиск/сортировку, экспорт с фильтрами, остановку, повторный запуск, прокрутку большой таблицы и предпросмотр.
6. Выбрать архив преподавателя «Для проверки Lab#2» после распаковки, сверить свойства с независимым просмотрщиком/ExifTool. Различать индексную глубину и глубину RGB-палитры, физический DPI и фиктивный default просмотрщика.
7. Опубликовать production dist на HTTPS-хостинге, проверить workers и выбор папки именно по публичному URL.

## Методика бенчмарка 600 JPEG / около 2 ГБ

- Использовать реальные исходные JPEG требуемого размера, не просто 600 маленьких копий из fixtures.
- Записать CPU/RAM/SSD, ОС, версию браузера, количество файлов и сумму размеров.
- Выполнить запуски с 1, 2, 4, 8 workers (и 16 при необходимости).
- Отдельно записывать время выбора/перечисления каталога и таймер Engine в приложении.
- Повторить по 3 раза; первый запуск может быть медленнее из-за файлового кэша. Не выдавать warm-cache за cold-cache.
- Сохранить CSV, время, число ошибок и объём запрошенных парсером байт. При необходимости контролировать RAM средствами браузера/ОС.
- Для 100 000 файлов отдельно проверять достижение конца списка, прокрутку и отзывчивость фильтра. Лимит допускается кодом, но реальный тест такого масштаба при подготовке архива не выполнялся.

Не подменять результаты измерений оценками и не обещать конкретный балл: решение проверяет преподаватель на своих файлах.
