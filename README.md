# Raster Inspector — лабораторная работа №2

Веб-приложение React + TypeScript. Бинарное чтение метаданных JPG/JPEG, GIF, TIF/TIFF, BMP, PNG и PCX. Изображения не отправляются на сервер; backend не требуется.

## Быстрый запуск

1. Установите Node.js 22 LTS (или совместимый Node.js 20.19+), если он не установлен.
2. Распакуйте архив и откройте терминал в папке, содержащей package.json.
3. Выполните:

```sh
npm install
npm run dev
```

Откройте адрес, напечатанный Vite (обычно http://localhost:5173). На Windows можно запустить START-WINDOWS.bat. Для первой установки зависимостей требуется интернет. node_modules в архив не входит.

Открывать index.html двойным щелчком нельзя: нужны Vite и загрузка модульных Web Workers по HTTP.

## Использование

- Нажмите «Выбрать папку», разрешите чтение; вложенные папки включаются автоматически.
- Либо выберите несколько отдельных файлов.
- Не более 100 000 файлов, включая файлы неподдерживаемых типов. Неподдерживаемые файлы выводятся как ошибки и не прерывают обработку остальных.
- Число workers можно выбрать перед запуском: 1–16. Начальное значение учитывает navigator.hardwareConcurrency и ограничено 8.
- Таблица показывает имя и путь, формат по сигнатуре, размер в пикселях, DPI по двум осям, глубину и сжатие.
- Фильтры: строка поиска по пути, формат, только ошибки. Сортировка: исходный порядок, имя, байты, ширина, глубина.
- Нажмите на строку: появятся подробные свойства, предупреждения и предпросмотр.
- CSV экспортирует все отфильтрованные строки, а не только видимые. Во время обработки экспорт отключён.
- «Остановить» завершает workers и оставляет отображённые результаты. Для повторного запуска выберите папку заново.

Для больших папок предпочтителен актуальный Chrome/Edge на компьютере. Перед передачей списка приложение браузер сам перечисляет выбранный каталог; время этого этапа не входит в таймер Engine.

## Сборка, проверка, публикация

```sh
npm test
npm run build
npm run preview
```

`npm run build` запускает TypeScript-проверку и создаёт production-каталог dist. Публиковать нужно содержимое dist, а не исходный index.html. Можно использовать любой статический хостинг с HTTPS, например Netlify, Vercel или GitHub Pages. Настройка build command: `npm run build`, output directory: `dist`. В Vite задан `base: './'` для относительных путей ресурсов.

На проверку по условию нужен публичный URL веб-приложения и исходники. Этот архив содержит исходники, но сам по себе не является публикацией. Проект из этой среды не размещался на хостинге.

## Независимые слои

```text
src/
  presentation/       React UI, виртуальная таблица, прогресс, CSV, превью
  core/               DTO, контракты, подготовка очереди, пул workers
  infrastructure/     Blob reader, worker-adapter, определение сигнатуры
    parsers/          отдельные побайтовые парсеры 6 форматов
  composition.ts      точка связывания Engine и Infrastructure
```

Core не импортирует React и реализации парсеров. Парсеры не импортируют UI/Engine. Слой Infrastructure использует DTO и контракт InspectorPort из Core. Worker создаётся фабрикой в composition.ts и передаётся Engine. UI не читает бинарные поля и не выбирает парсер.

Описание полей, формул, ограничений и ответы для защиты: `docs/REPORT.md`. Методика проверки и честный статус выполненных проверок: `docs/TESTING.md`.

## Статус проверки этого архива

- Синтаксис всех TS/TSX файлов обработан Babel в среде подготовки.
- 31 автоматический тест парсеров и Engine выполнен: 31 passed, 0 failed. Для выполнения здесь использовано преобразование TS → JS Babel и Node.js test runner. Пользовательская команда `npm test` запускает те же тесты через tsx.
- Production build и `tsc` здесь НЕ выполнены: нужные пакеты React/Vite/TypeScript отсутствуют в offline npm cache, интернет в среде отключён. Браузерные UI-тесты не выполнялись.
- Архив преподавателя «Для проверки Lab#2» не был предоставлен. Соответствие каждому его файлу не проверено.
- Реальный тест 600 JPEG / около 2 ГБ и нагрузка на 100 000 файлов здесь не выполнялись. Это лимит и архитектурная цель, а не подтверждённый результат бенчмарка.
